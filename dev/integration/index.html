Integration overview

CausalDynamics.jl owns causal graph structure, identification certificates, and executable discrete-time and static structural models. Downstream statistical estimation, probabilistic inference, causal discovery, continuous ODE integration, and plotting live in sibling packages or optional package extensions so core dependencies remain minimal.

Estimation bridges (CausalTargeted, TMLE.jl, Turing.jl)

CausalTargeted.jl (primary longitudinal and LMTP bridge)

For longitudinal treatments, modified treatment policies (LMTP), two-part hurdle outcomes, marginal structural models, Super Learner nuisances, and Bayesian g-computation, pass a TemporalUnrolling and TemporalEffectQuery from CausalDynamics to CausalTargeted.plan_targeted_estimation, then execute the returned EstimationPlan with CausalTargeted.run_estimation_plan.

  • CausalDynamics supplies structural identification (identify, IdentificationResult), wide-panel mapping (CDMPanel, simulate_panel, panel_column_name), and empirical support checks (identification_support).
  • CausalTargeted selects the estimation engine (:discrete_lmtp, :sequential_lmtp, :lmtp_grid, or :two_part_discrete_lmtp) and fits the nuisance and target estimators.

See the Identification API and the CausalTargeted.jl documentation.

TMLE.jl (optional point-treatment estimation)

For point-treatment targeted maximum likelihood estimation on tabular data with TMLE.jl, CausalDynamics provides three helpers:

  • prepare_for_tmle(g, X, Y; node_names=nothing) returns (confounders, is_identifiable) using backdoor identification.
  • get_tmle_confounders(g, X, Y; node_names=nothing) returns the confounder vector directly.
  • estimate_effect(g, data, X, Y; node_names=nothing, method=:tmle, kwargs...) combines identification and estimation when TMLE is loaded (for a CausalGraph with attached data, data may be omitted).

Optional compatibility note: TMLE.jl is not a dependency or weak dependency of CausalDynamics.jl. prepare_for_tmle and get_tmle_confounders work with core CausalDynamics alone. estimate_effect inspects loaded modules at runtime for TMLE (activated via using TMLE) and delegates to TMLE.tmle(data; treatment=..., outcome=..., confounders=..., kwargs...). Ensure that any extra kwargs... match your installed TMLE.jl version.

using CausalDynamics, Graphs, DataFrames

# Causal graph: Z → X → Y, Z → Y
g = DiGraph(3)
add_edge!(g, 1, 2)  # Z → X
add_edge!(g, 1, 3)  # Z → Y
add_edge!(g, 2, 3)  # X → Y

node_names = Dict(1 => :Z, 2 => :X, 3 => :Y)
confounders, identifiable = prepare_for_tmle(g, 2, 3; node_names = node_names)
# Returns: ([:Z], true)

# Simulated tabular data
n = 200
z = randn(n)
x = Int.(z .+ randn(n) .> 0)
y = 1.5 .* x .+ 0.8 .* z .+ 0.5 .* randn(n)
data = DataFrame(Z = z, X = x, Y = y)

# Once `using TMLE` is loaded in your environment:
# result = estimate_effect(g, data, 2, 3; node_names = node_names)

See examples/tmle_integration.jl in the package repository for additional examples (no confounding, multiple confounders, and CausalGraph auto-detection).

Turing.jl (probabilistic programming bridge)

CausalDynamics prepares identified adjustment sets and extracts tabular data for Turing.jl via prepare_for_turing and get_data_for_ppl:

  • prepare_for_turing(g, X, Y; node_names=nothing, data=nothing) returns a NamedTuple with fields graph, treatment, outcome, confounders, data, node_names, and is_identifiable. When g is a CausalGraph, attached node names and data are extracted automatically if omitted.
  • get_data_for_ppl(g::CausalGraph; format=:dataframe) converts attached graph data to :dataframe, :namedtuple, or :dict (returning nothing if no data are attached).
using CausalDynamics, Graphs, DataFrames

g = CausalGraph(3)
add_edge!(g, 1, 2)  # Z → X
add_edge!(g, 1, 3)  # Z → Y
add_edge!(g, 2, 3)  # X → Y
set_node_prop!(g, 1, :name, :Z)
set_node_prop!(g, 2, :name, :X)
set_node_prop!(g, 3, :name, :Y)

n = 200
z = randn(n)
x = randn(n) .+ 0.6 .* z
y = 1.8 .* x .+ 0.7 .* z .+ 0.5 .* randn(n)
attach_data!(g, DataFrame(Z = z, X = x, Y = y))

spec = prepare_for_turing(g, 2, 3)
# spec.treatment == :X, spec.outcome == :Y, spec.confounders == [:Z], spec.is_identifiable == true

nt = get_data_for_ppl(g; format = :namedtuple)

You can then pass the extracted columns and identified adjustment variables into a Turing model:

using Turing

@model function backdoor_linear(y, x, z)
    α ~ Normal(0, 2)
    τ ~ Normal(0, 2)
    β ~ Normal(0, 2)
    σ ~ Exponential(1)
    y .~ Normal.(α .+ τ .* x .+ β .* z, σ)
end

if spec.is_identifiable
    model = backdoor_linear(nt[spec.outcome], nt[spec.treatment], nt[spec.confounders[1]])
    chain = sample(model, NUTS(), 500)
end
